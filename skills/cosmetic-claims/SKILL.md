# cosmetic-claims

좋은 문구도 근거가 없으면 쓸 수 없다. 이 스킬은 기획과 카피에 들어간 표현을 하나씩 꺼내
"무엇이 이걸 받치나"를 묻고, 답이 없는 것을 걸러 RA에게 넘긴다.

사용자가 `/cosmetic-claims` 뒤에 쓴 것: `$ARGUMENTS`

**법률 판단이 아니다.** 이 점검은 빠뜨리기 쉬운 것을 찾는 체크리스트다. 써도 되는지는
RA(규제 담당)와 필요하면 법무가 정한다. 결과물 맨 위에 이 말을 쓴다.

## 공통 규칙 (모든 cosmetic-* 스킬)

- 작업 폴더는 `cosmetic/<프로젝트-슬러그>/`다. 어느 프로젝트인지 확인한다.
- 사실이 아닌 것을 만들지 않는다. 추정은 '가설', 모르는 것은 '확인 필요'. 숫자는
  출처와 확인일.
- 경쟁사 문구를 베끼지 않는다. 효능, 1위, 근거 없는 수치를 만들지 않는다.
- beauty-data MCP는 있으면 쓰고 없으면 공개 자료로 내려간다. MCP 데이터(카피 원문,
  OCR, 처방, 공급사, 가격)는 내부용이고 외부 게시물에 옮기지 않는다.

## Step 1: 표현 모으기

점검 대상: 사용자가 준 문구, 그리고 프로젝트 폴더의 `pitch.md`, `brand.md`,
`design-brief.md`, `marketing.md`, `pricing.md`, `formula.md`(기능성 목표), 상세페이지 초안.
문장 단위로 표현을 꺼낸다. 같은 표현이 여러 곳에 있으면 한 줄에 위치를 모두 적는다.

## Step 2: 종류 붙이기와 체크리스트

| 종류 | 예 | 확인할 것 |
| --- | --- | --- |
| 기능성 | 미백, 주름 개선, 자외선 차단, 여드름성 피부 완화, 탈모 증상 완화 | 기능성 보고·심사가 끝났나(번호, 날짜). 끝나기 전엔 표기하지 않음. RA 확인 필요 |
| 효능 단정·의약품 오인 | 치료, 예방, 완치, 재생, 염증, 아토피, 살균, 처방 | 화장품이 말할 수 없는 영역인지. 대부분 삭제나 수정 |
| 숫자 | 잔향 N시간, 보습 N%, N배, 자연유래 N%, N가지 성분 | 시험 보고서(기관, 날짜, 대상 수, 조건)나 계산 근거. 숫자는 시험 조건과 함께 써야 하는지 RA 확인 |
| 순위·수상·판매량 | 1위, 누적 N개, 어워드 | 출처, 카테고리, 기간, 기준일. 경쟁사의 순위를 우리 말로 쓰지 않음 |
| 시험 표현 | 피부과 테스트 완료, 저자극, 인체적용시험, 논코메도제닉 | 시험 기관, 날짜, 시험 종류, 결과 문서. 시험 전엔 쓰지 않음 |
| 성분 강조 | ○○ 함유, 고함량 ○○ | 실제 처방에 들었나(랩), 함량 표시가 필요한지(RA) |
| 비교·최상급 | 최고, 유일, 최초, 가장 | 비교 대상과 근거. 대부분 수정 |
| 무첨가·프리 | 설페이트 프리, 무파라벤, 무향 | 실제 처방과 맞나(랩), 표현 방식이 허용되는지(RA) |
| 천연·유기농·비건·인증 | 천연, 유기농, 비건, EWG, 더마 | 인증서, 인증 범위, 기준. 사이트 등급은 인증이 아님 |
| 가격·할인 | 정가 대비 N%, 최저가, 한정 | 그 정가에 실제로 팔았나, 기간, 비교 대상 |
| 추천·후기 | 고객 후기, 만족도 N% | 실제 후기·조사인가. 시뮬레이션 패널 답은 절대 아님 |
| 광고 표기 | 인플루언서 게시물 | 유료 협찬이면 광고 표기 |

근거를 찾을 때:

- 사내 자료(시험 보고서, 기능성 보고, 처방)는 사용자나 랩에 요청한다. 없으면 '근거 없음'.
- beauty-data MCP가 있으면 `analyze_inci_list`로 기능성 고시 성분, 향료 알러젠 같은 플래그를
  본다. 이건 성분 플래그이지 완제품 효능 근거가 아니다.
- 경쟁 제품이 같은 표현을 쓴다는 것(`copy_patterns`)은 근거가 아니다.
- 확인할 곳(현행 버전은 RA가 확인): 「화장품법」의 표시·광고 관련 조항, 식품의약품안전처의
  화장품 표시·광고 관련 고시와 가이드라인, 기능성화장품 관련 규정, 표시·광고 실증 관련 규정,
  공정거래위원회의 추천·보증 관련 심사지침(인플루언서). 조항 번호나 문구를 기억으로 인용하지
  않는다.

## Step 3: 상태 정하기

| 상태 | 뜻 |
| --- | --- |
| `통과` | 근거 문서가 있고 표현이 그 범위 안. 근거를 `evidence`에 |
| `수정` | 근거 범위에 맞게 고칠 문장을 제안함. 제안 문장도 다시 점검 |
| `삭제` | 쓰지 않기로 함 |
| `RA 확인 필요` | 근거는 있거나 생길 예정이지만 표현 허용 여부를 RA가 봐야 함 |
| `근거 없음` | 지금 쓰고 있는데 근거가 없음. 이 상태가 남아 있으면 cosmetic-plan 판정이 '아직' |

수정 제안은 효능을 약하게 바꾸는 게 아니라 **근거가 말하는 만큼만** 말하게 하는 것이다.
예: "잔향 N시간" → (시험 없으면) 삭제, 향의 장면을 말하는 문장으로 대체.

## Step 4: 쓰기

`cosmetic/<슬러그>/claims.csv`:

`expression,where,type,evidence,status,note`

`cosmetic/<슬러그>/claims.md`:

1. 맨 위: "법률 판단이 아님. 최종 확인은 RA."
2. 상태별 건수.
3. 표 (claims.csv와 같은 내용).
4. 고친 문장 목록 (전 → 후).
5. RA 질문 목록: 번호, 표현, 질문, 필요한 근거 문서.
6. 쓰지 않는 말 목록: 브랜드·마케팅이 그대로 가져다 쓸 수 있게.

## 규칙

- 근거를 만들지 않는다. 시험·보고가 없으면 '근거 없음'이다.
- 경쟁사의 근거를 우리 근거로 쓰지 않는다.
- 해외 판매(미국, EU, 중국 등)는 나라마다 다르다. 이 점검은 국내 기준이고 해외는 RA 확인 필요.
- 시뮬레이션 구매자 답, 내부 의견은 후기·만족도 근거가 될 수 없다.

## 출력

`cosmetic/<슬러그>/claims.csv`, `cosmetic/<슬러그>/claims.md`. 다음: `/cosmetic-brand`와
`/cosmetic-marketing`은 `통과`(또는 수정 뒤 통과)한 표현만 쓴다.
