# cosmetic-plan

마지막 단계. 상품기획 팀이 바로 쓸 수 있고, 랩과 경영진에게 넘길 수 있는 문서를 앞
스킬들이 찾은 것만으로 만든다.

사용자가 `/cosmetic-plan` 뒤에 쓴 것: `$ARGUMENTS`

## 공통 규칙 (모든 cosmetic-* 스킬)

- 작업 폴더는 `cosmetic/<프로젝트-슬러그>/`다. 어느 프로젝트인지 확인한다.
- 사실이 아닌 것을 만들지 않는다. 추정은 '가설', 모르는 것은 '확인 필요'. 숫자는
  출처와 확인일.
- 경쟁사 문구를 베끼지 않는다. 효능, 1위, 근거 없는 수치를 만들지 않는다.
- beauty-data MCP는 있으면 쓰고 없으면 공개 웹으로 내려간다. MCP 데이터(카피 원문,
  OCR, 처방, 공급사, 가격)는 내부용이고 외부 게시물에 옮기지 않는다.

## 도구

```bash
python3 "${CLAUDE_SKILL_DIR}/compile_plan.py" --dir cosmetic/<슬러그>
```

## Step 1: 무엇이 있나

```bash
python3 "${CLAUDE_SKILL_DIR}/compile_plan.py" --dir cosmetic/<슬러그> --check
```

판정과 검사를 출력한다. 검사는 모두 계산이다.

1. 모든 구성이 주문마다 남는다(부가세, 수수료, 배송비를 뺀 뒤) (`numbers.json`).
2. BEP가 초도 물량 안에 든다. 기준은 `--max-sell-through`(기본 1.0 = 100%). 바꾸면 이유를 적는다.
3. 재발주부터 개당 이익이 0보다 크다.
4. 시뮬레이션 구매자 구매율이 기준 이상이다(`panel/results.json`, 기본 25%, `--min-buy-rate`).
5. `claims.csv`에 `근거 없음` 상태가 남아 있지 않다. `RA 확인 필요` 건수는 함께 보여 준다.

`numbers.json`이 없으면 판정은 미완성이다. `/cosmetic-cfo`를 권한다. 빠진 섹션은 그걸 채울
스킬과 함께 목록으로 보여 준다. **빠진 섹션을 짐작으로 채우지 않는다.**

## Step 2: 이 스킬이 쓰는 네 파일

앞 스킬의 결과에서만 가져와 쓴다. 문장마다 어느 파일에서 왔는지 알 수 있게.

- `concept.md` (1. 제품 컨셉): 한 줄 컨셉, 타깃, 사용 장면. `brief.md`, `brand.md`,
  `marketing.md`의 포지셔닝에서.
- `usp.md` (5. USP): 3~5개. 각각 경쟁 대비 무엇이 다른지와 근거 행(`competitors.csv`,
  `claims.csv` 통과 행, `formula.md`). 근거가 없는 USP는 '가설'로 표시하거나 뺀다.
- `next-steps.md` (10. 다음 단계): 랩, RA, 부자재, 디자인, 상표, 판매 각각의 다음 할 일,
  누가, 열린 질문. 사용자가 결정해야 할 것은 번호 목록으로 따로.
- `summary.md` (요약): 반 쪽. 무엇을 누구에게, 판정과 그 뒤의 숫자 세 개(BEP·소진율, 완판
  시 이익, 재발주 개당 이익), 패널과 경쟁 분석이 같이 말하는 것과 다르게 말하는 것, 가장 큰
  위험과 대응, 이번 주에 할 한 가지. 판정이 '아직'이면 무엇을 바꿔야 하고 어느 스킬이
  바꾸는지로 시작한다. 실패한 검사를 부드럽게 쓰지 않는다.

## Step 3: 컴파일

```bash
python3 "${CLAUDE_SKILL_DIR}/compile_plan.py" --dir cosmetic/<슬러그>
```

두 파일을 쓴다.

- `product-plan.md` (상품기획서): 제목, 판정과 검사, 핵심 숫자 표, 요약, 1. 제품 컨셉,
  2. 개발 근거(경쟁 제품, 구매자 패널), 3. 성분 리서치, 4. 제형 기획, 5. USP, 6. 가격과
  원가·BEP, 7. 표시·광고 점검, 8. 브랜드와 패키지, 9. 마케팅, 10. 다음 단계, 부록 출발 메모,
  아직 없는 것.
- `dev-request.md` (개발 의뢰서): 용량, 내용물 목표 원가(원/g), 개당 목표 원가와 부자재
  항목, 초도 물량, 제형 기획, 컨셉 원료와 성분, 표시·광고 제한, 패키지 디자인 브리프.

제목은 `brief.md`의 첫 줄 `# 제목`에서 온다.

## Step 4: 사용자에게

판정 한 줄, 숫자 세 개, 사용자가 결정해야 할 것(번호 목록), 이번 주에 할 한 가지.
Word·PDF·슬라이드가 필요하면 내보내기를 제안하되, 마크다운이 원본이다.

## 규칙

- 판정은 `compile_plan.py`가 정한다. '추진 가능'을 손으로 쓰지 않고, 실패한 숫자를 반올림해
  통과로 만들지 않는다.
- 구매자 패널은 시뮬레이션이고 숫자는 입력값에서 나온 예측이라고 한 번 분명히 말한다.
  실제 견적, 랩 시험, RA 확인, 실제 판매로 굳힌다. 법률·세무 자문이 아니다.
- 기획서와 의뢰서는 내부 문서다. 처방 %·공급사·원가·경쟁 카피 원문이 들어갈 수 있는 자리가
  있으니 외부(고객사, 유통사, 공개 저장소)에 그대로 보내지 않는다. 외부용이 필요하면
  내부용 항목을 뺀 판을 따로 만든다.

## 출력

`cosmetic/<슬러그>/summary.md`, `concept.md`, `usp.md`, `next-steps.md`, `product-plan.md`,
`dev-request.md`. 그다음 판정 한 줄과 이번 주에 할 한 가지.
